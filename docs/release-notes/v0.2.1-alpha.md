# Kinfold v0.2.1-alpha

> Republish of v0.2-alpha with reproducible binaries: three v0.2-alpha
> binaries were stamped `+dirty` by the release script (#56) and did not
> match a rebuild. The code is identical to v0.2-alpha apart from the release
> script fix.

First alpha of Kinfold, the self-hostable relay-based overlay network
previously developed as the `my-zerotier` prototype (`v0.1-copilot`). This
release hardens, documents and packages the existing design; it does not add
a new transport. It has **not been independently audited** — use it for
evaluation and non-critical networks.

## Upgrade notes

- **Update the controller and all clients together.** The relay header was
  renamed (`X-Kinfold-Config-Revision`), so pre-rename and post-rename nodes
  cannot talk to each other.
- The binary is now `kinfold`, the default interface `kf0`.
- A state without a `policy` section no longer means allow-all: `serve`
  refuses it until you run `policy-enable` and add rules.
- The controller refuses `state.json`, credentials and private keys that
  other users can read (`chmod 700` directories, `chmod 600` files;
  `KINFOLD_INSECURE_PERMISSIONS=1` for volumes without modes).
- The IPv4 overlay network must be RFC 1918 or 100.64.0.0/10 space; IPv6
  values must be canonical. Hand-edited states that violate this no longer
  load.
- Go toolchain pinned to 1.26.10 (`go.mod`).

## Security fixes (from the code review)

- Controller connection exhaustion (high): idle keep-alive connections could
  hold listener slots forever, including for removed devices. All server
  timeouts are now set, error responses close the connection, connections are
  limited per source address, HTTP/1.1 only.
- Configuration without a policy meant allow-all and skipped the relay's
  revision check.
- Device certificates in the state are validated for shape (leaf, Ed25519,
  client+server auth, CN = ID); overlay network restricted to private space.
- Secret files readable by others are refused; the state directory itself is
  locked.
- `ip` is executed only from fixed system paths; the TUN device is created
  exclusively.
- Connection limits are counted per IPv4 address or IPv6 /64 (default 128
  per source), with bounded bookkeeping.
- Workflow actions are pinned to commit SHAs.

## Reliability fixes

- Relay: sessions revoked outside the global lock (no 5 s stalls per stuck
  peer); a reconnect replaces a stale session instead of being rejected for
  minutes.
- Client: 10 s per-frame write deadline and ~30 s keepalive detect dead
  paths; fresh send queue per session; tunnel kept through 30 s controller
  outages; failed tunnel restarts are retried; config polling reuses one
  connection.

## New features

- Automatic online renewal of device certificates with locally generated
  keys (`run -auto-renew`, `kinfold renew`); interrupted renewals resume
  safely after a lost response or a crash.
- `renew-server -server host:port` moves the controller without
  re-enrolling devices.
- `kinfold version`, structured logging (`-log-format`, `-log-level`).
- Hardened systemd units (`packaging/systemd/`), reproducible release builds
  with `SHA256SUMS`.

## Quality assurance

- Full code review of the prototype by four independent passes, plus an
  independent review of all alpha changes before release; every finding is
  fixed or documented (`docs/review-v0.1-copilot.md`).
- Race-enabled unit tests, five fuzz targets, an end-to-end Docker test with
  three clients over real TUN devices (12 scenarios), systemd units started
  under systemd 252.

## Documentation

README in English with an alpha overview; operator guide
(`docs/OPERATIONS.md`); security model, architecture decisions, a decision
log covering every choice made in this release, and the full code review of
the prototype (`docs/review-v0.1-copilot.md`).
