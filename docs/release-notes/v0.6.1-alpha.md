# Kinfold v0.6.1-alpha

Maintenance release: eleven fixes from a review of the whole code base
(#121 to #131). No new features. Builds on v0.6.0-alpha; not independently
audited — use it for evaluation and non-critical networks.

## Upgrade notes

- No protocol, state format or option change: v0.6.1 controllers and
  clients work with v0.6.0 and v0.5 ones. Replace the binaries; updating
  everything together is still recommended.
- A running controller now logs certificate expiry warnings once a day.
  Alert on `certificate ... expires on ...`.
- Two error messages changed, see "Fixes".

## Fixes

- **Certificate expiry no longer comes without a warning (#121).** `serve`
  warned about certificates that expire within 30 days only at startup. A
  controller that ran longer than that never warned, and one year after
  `init` its server certificate expired, the relay closed and every tunnel
  with it. The warnings are now repeated once a day (D-041).
- **`join` keeps its pending enrollment after a network error (#122).**
  `<out>.joining` was removed whenever the error text contained `403`,
  which includes a controller address such as `vpn.example.com:8403`. A
  lost answer then lost the key of a certificate that had already been
  issued. The file is now removed only when the controller refuses the
  token.
- **The 30-second grace period holds (#123).** A device keeps its tunnel
  for 30 seconds while no controller is reachable. The time was counted
  from the first failed answer, so slow timeouts stretched it to about 46
  seconds with one controller and to more than a minute with standbys. It
  now counts from the start of the first failed fetch (D-042).
- **`-max-conns-per-ip 0` no longer slows reconnects down (#127).**
  Disabling the per-source connection limit reduced the connection burst
  to 1. It now stays at the default of 128.
- **Client files survive a power loss (#129).** `<credential>.seen` and
  `<credential>.controllers` are written with a directory sync, like the
  credential itself.
- **Changed messages.** A state file with an invalid controller address
  is refused with `server must be a host:port address ...` or
  `server port must be between 1 and 65535 ...` instead of
  `invalid controller address` / `invalid controller port` (#125). A
  certificate mismatch on a relayed session reads
  `peer certificate does not match the authorized peer`, as on the direct
  path (#126).

## Internal

- The relay path and the direct path check the peer certificate with the
  same function (#126); `init` and `renew-server` build the server
  certificate with the same function (#125).
- Each sent packet is copied once instead of twice (#131).
- Less code (84 production lines net, fixes included): one flag parsing helper instead of 28 copies
  (#124), one atomic file writer (#129), no wrappers that only tests
  called (#130), no dead inode comparison in the token cache (#128).

## Quality assurance

The fixes come from a review of the whole code base at v0.6.0-alpha. An
independent review of all changes before this release found no
correctness or security issue and one low one: the new test of the grace
period had a thin timing margin, which was widened. Race tests, five fuzz
targets (30 s each) and the Docker integration test pass. The macOS
end-to-end test was not repeated, because neither the tunnel code for
macOS nor its packaging changed; the Linux and macOS binaries share the
changed send path, which the Docker test covers on Linux only.
