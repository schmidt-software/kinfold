# Kinfold v0.3.0-alpha

Operations and onboarding release. Builds on v0.2.1-alpha; not independently
audited — use it for evaluation and non-critical networks.

## Upgrade notes

- **Update the controller and all clients together.** The relay now checks a
  per-device configuration revision; v0.2 clients cannot open relay sessions
  with a v0.3 controller and vice versa.
- The controller state gains the optional field `enrollment_tokens`; v0.2
  binaries cannot read a state that contains pending tokens.
- The controller's TLS handshake no longer requires a client certificate;
  every endpoint except `POST /enroll` still does. Firewalls or monitoring
  that relied on handshake failures for unauthenticated clients now see HTTP
  403 responses instead.

## New

- **Per-device configuration and targeted invalidation (#20).** Each device
  receives only itself, the devices it has a rule with and those rules. A
  change closes only the relay sessions of affected device pairs, and clients
  apply changes that keep their own address without recreating the tunnel:
  adding a device or a rule no longer interrupts unrelated traffic.
- **Metrics (#25).** `serve -metrics` and `run -metrics` expose Prometheus
  text-format metrics on a loopback address: relay load, configuration
  reloads and availability, closed sessions by reason, rejections, renewals,
  enrollments; per-peer session state and traffic, dropped packets by
  reason, controller reachability and certificate expiry on clients.
- **Online enrollment with single-use tokens (#23).** `kinfold token` issues
  a token bound to a device ID and address (default lifetime one hour);
  `kinfold join` enrolls the device with a locally generated key after
  verifying the controller against a pinned CA fingerprint.
  `token-list` and `token-revoke` manage pending tokens. The token is read
  from a file or standard input, and an enrollment whose response was lost
  can be completed by running `join` again.

## Quality assurance

An independent review of all changes before the release found one medium
and six low issues, all fixed (see `docs/review-v0.1-copilot.md`). Race
tests, five fuzz targets and the Docker integration test (13 scenarios,
including metrics) pass.

## Decisions

D-021 to D-024 in `docs/DECISION-LOG.md`: scope of the post-alpha work, the
split into the releases v0.3/v0.4/v0.5, per-device views and targeted
invalidation, and token enrollment.
